El \dfn{backend} expone su funcionalidad mediante una \acs{api}
\acs{rest} versionada bajo el prefijo \texttt{/api/v1/}. Todos los
\textit{endpoints} siguen convenciones uniformes:

\begin{itemize}
  \item \textbf{Formato de errores.} Toda respuesta de error incluye un
  campo \texttt{error\_code} con un código simbólico independiente del
  idioma. Los errores de validación (HTTP~400) añaden un mapa
  \texttt{errors} con códigos por campo.

  \item \textbf{Paginación.} Todos los listados utilizan paginación por
  \textit{offset} con metadatos (\texttt{count}, \texttt{page},
  \texttt{page\_size}, \texttt{total\_pages}).

  \item \textbf{Autenticación.} Los \textit{endpoints} protegidos
  requieren un \textit{token} \acs{jwt} en la cabecera
  \texttt{Authorization: Bearer <token>}. Los \textit{endpoints} de
  autenticación (\texttt{/auth/login/}, \texttt{/auth/refresh/},
  \texttt{/auth/logout/}) y el \textit{health check}
  (\texttt{/health/}) son públicos.

  \item \textbf{Documentación.} El esquema OpenAPI~3.x se genera
  automáticamente a partir del código mediante la extensión de Django
  \texttt{drf-spectacular},
  garantizando que la documentación permanece sincronizada con la
  implementación. El esquema completo se incluye en
  \cref{AP:OPENAPI}.
\end{itemize}
